# Media-worker protocol v1 (M1–M4, T3)

`workers/media/protocol.ts` is the source of truth for schemas and inferred TypeScript types. `client.ts` is main/Node-only; `server.ts` is an independently bundled process. `electron/mediaWorker.ts` lazily owns the app's client and explicit tool configuration, and main waits for client shutdown before quitting. The renderer/preload API is unchanged.

## Running the implemented diagnostics

No FFmpeg installation, download or media fixture is needed for the real separate-process identity operation:

```sh
npm run smoke:media-worker
```

With a locally provisioned matching pair, supply **both absolute executable paths** (use `.exe` on Windows). Arguments are positional; quote paths containing spaces in the invoking terminal:

```sh
npm run smoke:media-worker -- '/absolute/tools/ffmpeg' '/absolute/tools/ffprobe'
```

This runs the actual tools with `['-version']` and `['-L']`, captures bounded version/configuration/license output and reports only indeterminate phases. It does not treat reported text as proof of a trusted build; source provenance and hashes belong to the artifact inventory. No media is opened and no percentage is invented.

M2 can additionally probe one real media file by passing a third absolute argument. The file is opened read-only; quote paths with spaces or Unicode in the invoking shell:

```sh
npm run smoke:media-worker -- '/absolute/tools/ffmpeg' '/absolute/tools/ffprobe' '/absolute/media/വീഡിയോ clip.mp4'
```

For the Electron-hosted smoke, after `npm run build:electron`, launch `electron . --media-worker-smoke` (or `./dev.sh smoke`). In unpackaged runs, main reads the pair from the gitignored `caption-studio.local.json` at the repository root (template: `caption-studio.local.example.json`; `./dev.sh` creates it on first run). Developer environment variables `CAPTION_STUDIO_FFMPEG_PATH` and `CAPTION_STUDIO_FFPROBE_PATH` override the matching keys; optional `CAPTION_STUDIO_MEDIA_SMOKE_PATH` adds a real probe. Packaged builds ignore the local file. Normal app startup creates no worker until needed. Malformed local configuration is reported with the file path, never silently ignored. No executable discovery through PATH or project JSON is supported; the local file is developer machine configuration, not project data. T3 adds `CAPTION_STUDIO_WHISPER_CLI_PATH`, accepted only together with the FFmpeg/ffprobe pair; see [TRANSCRIPTION.md](TRANSCRIPTION.md) and `npm run smoke:transcription`.

Main-process usage:

```ts
const job = getMediaWorker().start({ operation: 'runtime' }, {
  onProgress(message) { console.log(message.progress) },
})
const result = await job.result // typed runtime result, including actual child PID
// job.cancel() or an AbortSignal may cancel an active job.
```

## Messages and validation

Transport: UTF-8 newline-delimited JSON over private child stdin/stdout pipes. Stderr is diagnostic only. Each line is bounded to 1 MiB **before parsing**, including fragmented chunks; partial final lines, invalid UTF-8/JSON, unknown versions/keys and invalid values fail closed. Every outgoing/incoming application message is parsed with strict Zod schemas. The client additionally verifies the request ID, operation and absence of messages after a terminal response. Worker execution never receives renderer-selected command-line flags.

A request is `{ version: 1, type: 'request', id: UUID, task: { operation, ...parameters } }`. Cancellation is `{ version: 1, type: 'cancel', id: UUID }`. The server accepts exactly one request per process, followed only by matching cancellation. Duplicate requests, invalid cancellation IDs and malformed messages abort the active operation and return `fatal` with a structured error; there is no guessed request ID for unparseable input.

Responses:

| Type | Fields and meaning |
| --- | --- |
| `progress` | Version, ID, operation and `progress`. Either `indeterminate` with a real phase, or `measured` with integer `completed`, positive `total`, and unit `sourceUs`, `items` or `frames`. `completed <= total`. M1 emits only actual running/inspection phases. |
| `result` | Version, ID and a result discriminated by operation. Full payload validation precedes resolution. |
| `error` | Version, ID, operation and `{ code, message, retryable, exitCode?, signal?, diagnostic? }`. Diagnostic text is capped at 8,192 characters. |
| `cancelled` | Version, ID and operation. A terminal acknowledgement after operation cleanup. |
| `fatal` | Version and structured error for a broken protocol/configuration; terminal for the connection. |

## Operation contracts

All media timestamps/durations are safe integer **source microseconds**, never accumulated frame-rounded seconds. Stream origins may be signed or unknown. Rates and time bases are rational numerator/denominator pairs; unknown probe fields are explicit nulls. Paths preserve spaces and mixed Malayalam/English. The wire accepts POSIX absolute, Windows drive-absolute and UNC syntax; execution checks the current host's absolute-path rules too. URLs, relative paths and NUL-containing paths are rejected.

| Operation | Request | Result | M1 implementation |
| --- | --- | --- | --- |
| `runtime` | No parameters | Actual PID, platform, architecture, Node version | Real worker process inspection |
| `inspectToolchain` | No parameters; paths owned by main configuration | Actual FFmpeg and ffprobe version/configuration and license output | Real read-only executable invocations |
| `probe` | Input path | Metadata plus sampled fingerprint. Metadata contains nullable integer-µs format duration, coded dimensions, rotation, exact average/nominal rational rates and typed audio/video/other stream codec/time-base/origin fields | Real read-only FFprobe JSON invocation and worker-owned fingerprinting (M2) |
| `waveform` | Input, source range, bounded maximum peak count | Range and bounded normalized peaks | Real cancellable FFmpeg decode to bounded mono float PCM, followed by absolute-peak reduction (M3) |
| `thumbnails` | Input, bounded requested source times (max 1,000), width, job output directory | Paths/dimensions with requested **and actual** source timestamps | Real cancellable per-timestamp FFmpeg decode to one `mjpeg` frame per requested time, with the actual decoded timestamp read from the `showinfo` filter (M4) |
| `extractAudio` | Input, source range, output path, mono, 16/48 kHz | Path, source origin, duration, sample rate and sample count | Real cancellable FFmpeg decode of the first audio stream to mono 16-bit WAV with `aresample=<rate>:async=1:first_pts=0`, `-n`, measured progress; duration from the WAV sample count, bounded by the range (T3) |
| `detectSilence` | Input, source range, dB threshold (≤ 0), minimum silence duration | Range, silence spans and the `speechGating` version they were produced with | Same 16 kHz mono extraction as `extractAudio`, streamed through the existing `LongSilenceDetector` (`src/core/speechGating.ts`, already used for transcription's silence gating) rather than a new detector; no disk cache, since the result depends on caller-supplied threshold/minimum-silence parameters (Remove Silence, 2026-09-18) |
| `inspectWhisper` | Absolute model path; executable owned by main configuration | whisper.cpp version, GPU backend whisper.cpp initialized (or null), verified CPU fallback, `system_info` | Real `--version` plus GPU-allowed and `-ng` model loads on a generated one-second silent WAV (T3) |
| `whisperTranscribe` | Job-owned 16 kHz mono WAV, model path, language or `auto`, GPU flag, audio window duration | Language, backends used, gating version, silences, chunks, audio-relative segments with explicit timing adjustments, dropped counts | Real exact long-silence gating, one WAV and one `whisper-cli -oj` run per speech chunk, measured `-pp` progress (T3) |
| `proxy` | Input, output path, known source duration | Output path and the FFmpeg-measured output duration | Real cancellable FFmpeg transcode to WebM/VP8/Opus, capped at 1280px on the longest side; never overwrites the input (M4) |
| `export` | Input paths (every file read), shared-renderer manifest path, range, output path, dimensions, rational rate and versioned profile | Path, duration, frame count and rational rate | Real cancellable render/encode (X2): one PNG frame per requested timestamp from the separate GPU export host, piped into `h264_videotoolbox`/AAC through the `mp4-caption-renderer-v1` profile ([ADR 0004](decisions/0004-mp4-export-profile.md)) |

For uniform waveform buckets, bucket edge `i` is `startUs + floor(i * (endUs - startUs) / peakCount)` using safe wide integer arithmetic; the last edge is exactly `endUs`. No rounded per-bucket duration is accumulated. M3 extraction version `ffmpeg-f32le-mono-peaks-v1` decodes the requested range to mono little-endian float PCM at an adaptive rate capped at 8 kHz and approximately 32 decoded samples per requested peak. Each result bucket is the maximum clamped absolute amplitude in its sample interval; it is not loudness normalization or estimated speech alignment. FFmpeg receives exact decimal source times, a mandatory first-audio-stream map and a bounded output size. The returned range remains the requested canonical source range and peak count never exceeds the request. Thumbnail actual times must come from decoded timestamps, not copies of the requested time. Missing timing data must remain unknown, never estimated alignment.

M4 extraction version `ffmpeg-mjpeg-showinfo-v1` spawns one FFmpeg process per requested timestamp: `-ss <requested> -copyts -i <input> -frames:v 1 -vf scale=<width>:-2,showinfo -c:v mjpeg -f image2 <job dir>/thumb-<index>.jpg`. `-copyts` is required — input seeking otherwise rebases decoded presentation timestamps to start near zero, which silently produced `actualUs: 0` for every thumbnail until this was caught and fixed during M4 real-media verification. The `showinfo` filter, placed after `scale` in the same run, reports the actually decoded frame's `pts_time` and post-scale `s:WxH`; the worker parses the first matching line (the frame FFmpeg's `-frames:v 1` limit keeps and writes to the output file, even though B-frame reordering can make `showinfo` log one extra look-ahead frame first) rather than trusting the requested seek time. A frame with no parseable `showinfo` output is a `TOOL_FAILED` error, never a fabricated timestamp. M4 proxy conversion version `ffmpeg-vp8-opus-webm-v1` runs one cancellable FFmpeg transcode of the whole input to `libvpx`/`libopus` WebM, video scaled to at most 1280px on the longest side, with real `-progress pipe:1` `out_time_us` progress identical in shape to the waveform's observer; the result's `durationUs` is the last measured `out_time_us`, not a copy of the request. Local proxy conversion needs FFmpeg built with both `--enable-libvpx` and `--enable-libopus`; `src/core/proxy.ts`'s `proxySupportFromConfiguration` parses the real `inspectToolchain` configuration string for both flags (cached for the app session) so the renderer only offers proxy controls when conversion is actually functional on the configured tool pair, never unconditionally.

`probe` invokes only the configured ffprobe executable with a fixed argument array and a final literal input path. Decimal seconds are converted directly to safe integer microseconds; frame rates remain rationals, including different `avg_frame_rate` and `r_frame_rate` values common in VFR media. Width/height remain coded dimensions and rotation remains separate. Unknown or `0/0` fields stay null. The fingerprint hashes a domain/version marker, file size and either the whole file up to 768 KiB or fixed 256 KiB beginning/middle/end samples for larger files. It is a fast relinking identity hint, not a full-file integrity guarantee; stored metadata is compared too. The file is re-statted to reject changes during hashing.

Waveform decoding creates one uniquely allocated job directory in the host temporary location and a new raw PCM output inside it. The directory is removed in `finally` after success, cancellation or failure; unrelated files are never cleanup targets. Main exposes waveform loading only for a media fingerprint registered by a successful probe in the current app session. Validated JSON peaks are atomically cached under the Electron user-data cache, outside Git, using a SHA-256 key over the full sampled-fingerprint record, source range, maximum peak count and extraction version. Cache contents are schema-validated and their identity/range/resolution are rechecked before use. Export's manifest must be separately versioned/validated with the shared caption renderer in X1; arbitrary FFmpeg filters/arguments are intentionally absent. Single-source edits ([EDITING.md](EDITING.md), V1–V6) extend that manifest to a v2 superset carrying kept segments, output-pixel blur regions and sequence-time audio-clip delays; the worker derives a deterministic, snapshot-tested filtergraph from it. Schema 5's stacked timeline adds manifest v3 ([ADR 0005](decisions/0005-stacked-export.md)): one input per FFmpeg-read clip (opened with `-ss`/`-t`), clips with stacking index, sequence position, output-pixel rect, opacity, fit and gain, and two filtergraph routes (flat `concat`; stacked black canvas + `tpad` + `overlay=eof_action=pass:repeatlast=0`). The task's `inputPaths` lists every file read so the worker refuses a destination equal to any of them, and every v3 input must be one the task declared; the worker probes each once for its audio stream and to refuse a clip past the end of its file by name. A flat single-video sequence still travels as v2 with byte-identical arguments. The renderer still never supplies a flag.

Thumbnail requests reuse the same registered-fingerprint gate. Main allocates one job directory per batch of cache misses, passes it as the `thumbnails` task's `outputDirectory`, reads each resulting JPEG into a base64 `data:` URL (the renderer has no filesystem access) and removes the job directory in `finally`. Each thumbnail is cached individually — outside Git, under Electron's user-data cache — keyed by fingerprint, requested timestamp, width and extraction version, so a batch at a new zoom level reuses any previously extracted timestamps that happen to still be requested and only asks the worker for genuine misses. Proxy conversion reuses the fingerprint gate and writes through a temporary file beside the user-chosen destination (an explicit native save dialog, never the source path) with the same atomic write-then-rename pattern as project/SRT saves; the temporary file is removed in `finally` whether or not the rename happened. `proxySupportFromConfiguration` (`src/core/proxy.ts`) is checked, and its result cached for the app session, before main will attempt a `proxy` job at all — an unsupported configuration returns `UNSUPPORTED_OPERATION` rather than spawning FFmpeg.

## Lifecycle and failure behavior

One short-lived worker per job keeps the boundary small. The client caps concurrent owned jobs at four; this is a simple ceiling on `MediaWorkerClient`, unrelated to job semantics. A job promise settles only after the worker closes. Cancellation before receipt of a terminal response wins; once a terminal response is received, a later cancel is a no-op. Requests with an already-aborted signal never spawn. `close()` stops accepting jobs, cancels all owned jobs and awaits their settlement.

[T1](TRANSCRIPTION.md) adds the separate queue/resource-arbitration layer this note used to defer: `electron/jobScheduler.ts` is a main-owned FIFO queue that keeps every heavy job kind (`transcription`, `alignment`, `export`) from running together by default. It is not yet wired to media-worker operations — waveform, thumbnail and proxy jobs still go directly through `MediaWorkerClient`'s own four-job cap, not the scheduler — so a large proxy conversion and a future transcription job are not currently arbitrated against each other. A later ticket should decide whether media-worker jobs route through the same scheduler. X2 (`electron/jobs.ts`'s `getJobScheduler()`) shares **one** scheduler instance between transcription and export specifically, so those two heavy kinds do arbitrate against each other today; waveform/thumbnail/proxy remain outside that scheduler.

X2's `export` job (`electron/exportService.ts`) writes a job-owned manifest to a `mkdtemp` directory, renders through the worker's `export` operation to a temporary path beside the user's chosen destination (`<destination>.<uuid>.tmp`, never the source path), and only renames onto the real destination after `ctx.enterCommit()` succeeds — a cancellation that arrives after a valid encode exists but before that rename still discards the completed file, matching T1's commit-gate contract. The job directory and any leftover temporary output are removed in `finally` on every outcome. Within the worker itself, a frame with no active cue is always fully transparent and identical, so one rendered gap PNG is reused for every later gap frame instead of a new export-host round trip per frame.

V2 adds an argv allow-list to the export host spawn: `workers/media/export.ts` appends one `--asset <url>` pair per unique overlay `assetUrl` in the manifest (`[...tools.exportHost!.scriptPath, '--user-data', hostProfileDirectory, ...assetArgs]`, still a plain argument array — no shell). `scripts/export-host.mjs` registers the `media` scheme privileged (mirroring `main.ts`) and, once its window exists, calls `session.protocol.handle('media', …)` that serves **only** an exact URL from that allow-list, decoded with the same `mediaPathFromUrl` main uses and read via `net.fetch(pathToFileURL(path))`. A frame request for a manifest with no overlays carries no `--asset` args at all and the host's behaviour is unchanged from X2.

The worker aborts direct tool execution on cancellation, stdin closure, SIGTERM or SIGINT, sends SIGTERM to its direct tool child, escalates to SIGKILL after 500 ms if necessary, and awaits child close before acknowledging. Normal completion flushes the response and exits. Each diagnostic command has a combined stdout/stderr limit of 64 KiB. The client deadline defaults to 30 seconds (main-configurable, up to 24 hours); after requesting cancellation it allows two seconds for worker cleanup before force-killing an unresponsive worker. Unexpected exit, output overflow, spawn failure, tool nonzero exit, protocol failure and timeout surface structured errors rather than hanging promises. Output after a terminal response is rejected.

This is process isolation, **not an OS security sandbox or crash-proof process-tree supervisor**. Approved tools are direct executables, not scripts that launch grandchildren. Normal cancellation/reaping is tested; SIGKILL of the parent, an OS crash, or a wedged worker can bypass graceful cleanup. D2 must assess platform process-tree containment and crash recovery before long-running media jobs are release-ready.

Node and Electron launch the worker with `spawn(executable, [workerPath], { shell: false })`. Direct tools use `spawn(toolPath, args, { shell: false })`; stdin is disabled for them. `path.join` and `process.execPath` avoid platform-specific runtime discovery. M1 uses Electron's existing `ELECTRON_RUN_AS_NODE=1` mode and removes inherited `NODE_OPTIONS`/`NODE_PATH` in the worker environment. D2 must keep worker artifacts outside ASAR and either retain the RunAsNode fuse or replace this transport with Electron utility processes before disabling it. [Electron environment variables](https://www.electronjs.org/docs/latest/api/environment-variables), [Electron fuses](https://www.electronjs.org/docs/latest/tutorial/fuses)

## Verification boundaries

`npm run check` includes worker TypeScript, protocol/probe/fingerprint/path/migration tests, deterministic waveform peak/time tests, deterministic thumbnail timestamp/`showinfo`-parsing/cancellation tests, deterministic proxy progress/cancellation tests, thumbnail-cache invalidation and cleanup tests, real-process tests and the separately bundled worker. Parser fixtures cover VFR-relevant dual rational rates and display-matrix rotation. Test-only dependency injection supplies deterministic PCM bytes, showinfo stderr fixtures and progress-stream fixtures for reducer/lifecycle tests; production extraction and smoke verification invoke the selected real FFmpeg executable. The default check requires no installed tools or network. Separate manual smoke runs exercised the real source-built FFmpeg pair and generated H.264/AAC media under Node and Electron on macOS arm64; the timeline showed the real SVG waveform, source-time seeking and zoom alignment, and a second load hit the cache. M4 rebuilt the pair with real `libvpx`/`libopus` support and exercised `probe`, `waveform`, `thumbnails` and `proxy` for real against two locally generated fixtures (Chromium-playable H.264/AAC and diagnostically unsupported native MPEG-4 Part 2/AAC) through both the Node smoke script and the Electron-hosted worker; see `docs/STATUS.md` for exact results and what remained unverified (interactive renderer/GUI behavior). Windows wire path syntax is tested; Windows execution/packaging is not claimed. T3's `extractAudio`, `inspectWhisper` and `whisperTranscribe` are covered by deterministic argument/offset/cleanup tests and by real FFmpeg plus whisper.cpp smoke runs recorded in `docs/STATUS.md`. X2's `export` operation (`workers/media/exportArguments.test.ts`, `src/export/plan.test.ts`, `src/core/exportSupport.test.ts`, `workers/media/export.test.ts`, `electron/exportService.test.ts`) is covered by deterministic argument-array/frame-timestamp/support/PNG-framing/cancellation/commit-gate/cleanup tests using fake spawned processes, plus a real end-to-end export, a real 30000/1001-rate export and a real mid-export cancellation recorded in [ADR 0004](decisions/0004-mp4-export-profile.md) and `docs/STATUS.md`; a real rotated-source export was not exercised this session.
