# Proposed architecture

## Boundaries
Electron main owns file dialogs, narrow IPC, jobs, local filesystem and worker lifecycle. Isolated React renderer owns UI and editing. Pure TypeScript core owns project schema, editing commands, validation, SRT parser/serializer and animation evaluation. A shared caption-rendering module calculates layout and visible state from project data plus an absolute timestamp.

Suggested directories when scaffolding: apps/desktop, packages/core, packages/caption-renderer, workers, tests/fixtures, docs. Keep this lean; use one package initially if separate packages add overhead.

**Local agent control ([MCP.md](MCP.md))** adds a fourth caller of the command layer, beside the UI, SRT import and transcription: an opt-in, loopback-only MCP server in Electron main (`electron/mcp/`) that a local Claude client can drive. It never gains its own copy of project state — every read and edit crosses one request/response IPC pair (`electron/mcp/rendererBridge.ts`) to the renderer's `useAgentBridge` (`src/agent/useAgentBridge.ts`), which applies the same `applyEditCommand`/`runCommand` path and the same undo history App.tsx's own controls use. The MCP-facing command schema (`src/core/editCommandSchema.ts`) is a zod mirror of `EditCommand`, checked at compile time against the real union so the two cannot silently drift.

The media bin's import paths add two IPC channels alongside the existing `assets:import`/`assets:relink`: `assets:import-files` (a multi-select native dialog filtered to image/audio/video/subtitle extensions) and `assets:inspect-dropped` (a zod-validated, ≤64-entry array of absolute paths). Both share `electron/assetInspect.ts`'s `inspectFileForBin`, which classifies a `.srt` as text without probing it and everything else through the media worker's probe (registering its fingerprint like every other `inspectMedia` call). An OS file drag never exposes a path to the renderer: the sandboxed preload resolves each dropped `File` to its path via `webUtils.getPathForFile` before invoking `assets:inspect-dropped`, so `src/core/assetImport.ts`'s `InspectedFile` result is the only shape the renderer ever sees.

Media worker: [ADR 0001](decisions/0001-media-worker-and-ffmpeg.md) selects separate FFmpeg/ffprobe CLI processes from project-controlled LGPL-2.1-or-later builds, initially upstream 9.0.1. [Protocol v1](MEDIA_WORKER.md) defines validated requests, progress, cancellation, structured errors and results in `workers/media/`; main owns the client and lifecycle. M1 implements real runtime/toolchain diagnostics, M2 implements read-only probing plus sampled media fingerprints, M3 implements cancellable bounded waveform extraction, and M4 implements cancellable zoom-aware thumbnail extraction plus a local WebM/VP8/Opus proxy-conversion path. Main caches validated peak data and individual thumbnails outside Git, keyed by fingerprint plus request identity and extraction version; the renderer receives only normalized peaks, base64 thumbnail images and canonical source-time bounds — it has no filesystem access. Codec diagnostics ask the real embedded Chromium `<video>` element (`canPlayType` and its actual `error` event) rather than a hardcoded codec matrix; proxy controls are gated on `src/core/proxy.ts`'s real, cached parse of the configured FFmpeg's own reported `-version` configuration, so they only appear when conversion is actually functional on the configured tool pair. T3 implements real audio extraction and the whisper.cpp inspection/recognition operations. No binaries are bundled yet. Rendering frames and final encoding must use the shared caption renderer; do not create an unrelated FFmpeg text implementation that changes shaping or wrapping. Remotion is not adopted. [ADR 0003](decisions/0003-export-renderer.md) selects X1's measured GPU-accelerated Electron offscreen CPU-bitmap renderer, using the actual shared preview adapter/painter and a font/committed-frame barrier; software mode is measured but differs from GPU preview pixels, so it is a fallback requiring an explicit tolerance policy. X2 ([ADR 0004](decisions/0004-mp4-export-profile.md)) implements the production `export` operation: the separate GPU export host and bounded PNG transport render into a real cancellable `h264_videotoolbox`/AAC `mp4-caption-renderer-v1` encode, gated by `src/core/exportSupport.ts`'s real configured-tool check (macOS only in this ticket) and exposed through the renderer's **Export Video** control only once that check succeeds.

Transcription worker adapter: [T1](TRANSCRIPTION.md) defines the typed contract in `src/core/transcription.ts`/`workers/transcription/`: capabilities(), transcribe(input, options, progress, cancellation), optional align() with its own explicit supported-language declaration independent of transcribe()'s — never assume an aligner supports Malayalam because transcription does. Adapters report timestamps relative to the audio file they were given; `workers/transcription/run.ts` performs the single source-time mapping and validates output before it can reach a project mutation. Use whisper.cpp as the initial integration candidate across platforms; benchmark faster-whisper as an optional Windows/NVIDIA adapter. Worker discovery, model formats and device support are explicit. No arbitrary-model-file compatibility promise. T1 established contracts plus the job scheduler, proven with a deterministic test-only adapter; [T2 model management](MODELS.md) adds a compiled five-artifact catalog (base, base.en, small, large-v3-turbo, large-v3), async main-owned streaming downloads/verification, atomic activation and ID-only IPC. Local final files are rehashed on listing and before main-only backend resolution. Download/resume requires an explicit click; selected-file removal requires native confirmation. CPU/Metal/CUDA entries show upstream build requirements, not detected devices. [T3](TRANSCRIPTION.md#whispercpp-integration-t3) integrates a project-built whisper.cpp 1.9.4 `whisper-cli` through the separate worker: main re-verifies the model, inspects the engine's real backends, extracts source-time-exact audio, gates long silences, runs one whisper-cli process per speech chunk and delivers validated, source-timed captions through the commit gate. The renderer applies them as one undoable step and requires an explicit keep/replace choice before touching existing captions. Transcription runs record engine/model provenance in the project.

Optional imported-SRT alignment is a separate BYOK path. Electron main encrypts the Gemini key through `safeStorage`, extracts only cue-covered ranges (500 ms padding, gaps under two seconds merged, 20-minute maximum chunks), uploads temporary WAV files to `gemini-3.5-transcribe`, requests verbatim Malayalam/English word timestamps with response storage disabled, and best-effort deletes every upload. Only exact normalized monotonic token matches cross the existing alignment validator; imported text/cue boundaries and manual word corrections remain authoritative. Unmatched tokens use the explicitly estimated local fallback. Renderer IPC sends a registered media fingerprint and cue snapshots, never a path or credential. No raw provider transcript or key is written to a project. Optional Gemini transcription follows the same key and bridge rules: the renderer sends `engine: 'gemini'`, a fingerprint and a language choice. The worker's `speechChunks` operation writes silence-gated speech WAVs, each chunk is recognized through the shared `geminiRecognition.ts` client, and the result passes through the same `runTranscription` validation as whisper.cpp. An optional `translateTo` target, offered for either transcription engine, adds one more step inside the same job, after recognition and before delivery: recognized segment texts (never audio) are sent to `gemini-3.8-flash` in indexed batches (`electron/geminiTranslation.ts`), validated for exact index/count alignment, and rechecked with the same script-mismatch sanity check recognition uses. Captions then carry the translated text with the recognizer's segment timing, estimated word timing and `needsReview: true`; the original spoken-language recognition and translation provenance are both retained on the run. The top bar groups actions by intent: captions workflow (Transcribe, Align audio when usable, job status, media-offline relink), a File menu, an Export menu and one Settings dialog (speech models, Gemini key, shortcuts). A native application menu forwards validated `menu:command` actions through preload and owns the ⌘/Ctrl+O/S/E accelerators.

## Project model

R1 implements the shared composition-space renderer in `src/captions/renderer.ts`, with the
font-ready DOM measurement/painter and scaling adapter in `CaptionPreview.tsx`. The real video
preview uses it; future Chromium export must reuse `CaptionView`, the same font readiness and
absolute source timestamp evaluator. See [renderer/font contract](CAPTION_RENDERER.md).
R2 adds the five motion presets and their appearance controls on this same renderer, with no
second implementation: `src/captions/style.ts` defines `CaptionStyle` (motion id plus a separate,
schema-validated appearance) and `SavedCaptionPreset`; schema 2's optional `captionStyle` and
`savedCaptionPresets` persist them so style is project state, saves/reopens and is undoable.
`src/StylePanel.tsx` is the real inspector control surface; `App.tsx` wires it to `CaptionPreview`
through one live draft (immediate preview feedback while dragging) committed to history per
finished gesture. See [motion presets](CAPTION_RENDERER.md#motion-presets-r2).
Schema version; project ID; media reference and fingerprint; source duration in integer microseconds; rational average/nominal frame rates and rotation; captions with stable IDs, start/end, text and words; word timing source (model, aligned, manual, estimated), needsReview flag; original transcript/import metadata; style/preset/word emphasis; engine/model provenance. Store optional confidence only if the engine supplies meaningful values. Use stable word IDs so edits do not attach emphasis to the wrong token.
Projects are saved to a `.cstudio` file (plain JSON under the hood; `PROJECT_FILE_EXTENSION` in `src/core/model.ts`). The Open dialog also accepts legacy `.json` project saves. Once a project has a path (Save As or Open), every history change is autosaved there after a one-second debounce (`project:write`, dialog-free, restricted in main to paths chosen through a dialog this session); ⌘/Ctrl+S writes in place and ⌘/Ctrl+Shift+S is Save As. A schema-migrated project is not rewritten until the user saves explicitly, so the original file survives. The native Edit menu forwards Undo/Redo to project history, or to the focused text field's own history when one is being edited. Since schema 4 ([EDITING.md](EDITING.md) "Schema 5" is current) every video is an asset of kind `video`, so it is saved, resolved and relinked exactly like image and audio assets, and `project:open` reports one resolution per asset rather than a separate media resolution; `project:save`/`project:write` take no media path. Each media record stores media metadata, the `sha256-sampled-v1` identity hint, a safe forward-slash relative path when media is below the project directory, and an absolute fallback. It never embeds or copies source bytes. Reopen tries the contained relative path before the native absolute fallback, probes it again and requires an explicit choice when identity differs. Keep media time canonical even with variable-frame-rate input. Export mapping handles output frame rate once.

T4 keeps recognition, word timing and readable grouping separate in `src/core/recognition.ts`,
`wordTiming.ts` and `captionGrouping.ts`, with grapheme-safe exact text spans in `captionText.ts`.
Schema-2 optional word text offsets/confidence and original recognition snapshots preserve compatibility;
word IDs are globally unique and microseconds/containment/order/text correspondence are validated.
Segment-only recognition gets review-required estimates; grouping never retimes word boundaries.
Text edits retain only safe unambiguous identities and mark missing alignment for review. Imported SRT
is never automatically grouped or estimated. See [T4 rules](TRANSCRIPTION.md#caption-grouping-word-provenance-and-corrections-t4).

**Schema 5 — a stacked multi-track timeline — supersedes the single-source model below** ([EDITING.md](EDITING.md) "Schema 5"): `project.tracks` (back to front) and `project.clips` (video, image and audio clips at absolute sequence positions, sorted by track then start, never overlapping on a track), sequence-timed blur, and `project.format` fixing the output frame and caption composition. Captions stay in the source time of the video they name; `src/core/timelineModel.ts` is the pure time model (`activeClipsAt`, `spansInSequence`, and `activeCueAt` — the one active-caption rule the preview, the export layer plan and the export frame requests all share), `src/core/clipEdits.ts` the NLE verbs (overwrite/ripple place, move, trim, split, delete, close gap), `src/core/migrateV4.ts` the 4 → 5 migration (gapless by construction, park-never-drop, reported). Commands split into `assetCommands.ts`, `trackCommands.ts` and `clipCommands.ts` behind `itemCommands.ts`'s one epilogue. Preview playback is `src/playback/`'s sequence clock (disciplined to the topmost playing video's presented frames), a pool of `<video>` elements per (track, asset) driven by the pure `transportActionsAt`, and the SFX scheduler on the transport's state; `CompositionLayers` paints video, image and blur layers under the captions. Export emits manifest v2 for flat sequences (byte-identical) and manifest v3 otherwise ([ADR 0005](decisions/0005-stacked-export.md)); main resolves every file the timeline plays through its fingerprint registry.

Single-source edits ([EDITING.md](EDITING.md), tickets V1–V6) — history: **V1–V2 were implemented on schema 3; schema 5 carries their items forward.**
Schema 3 adds `assets` (image/audio references reusing the media reference/fingerprint/relink model),
`overlays`, `blurRegions`, `audioClips` and an optional kept-range `segments` edit list, with one ID
namespace across every kind and `assetId` kind matching enforced in `superRefine`. `loadProject`
accepts 3, 2 and 1. Every item is stored in source-media microseconds; `src/core/sequence.ts` is the
single pure mapper to sequence time, which only the ruler/playhead, transport clock, cut-project SRT
export and export frame iteration use — `currentUs`, cues, `captionFrame`, transcription and every
media-worker request and cache key stay in source time. Cues that straddle a cut are clipped for
display/export, never split in storage. Item edits are a second command union (`itemCommands.ts`)
dispatched with `captionCommands.ts` through `commands.ts`'s `applyEditCommand`, sharing
`CommandResult`/`ValidationIssue` and the whole-project undo history; rect height is a command-time
warning via `CommandContext.compositionHeight`, never a schema error, so a relink to a different
aspect cannot make a project unloadable. `Timeline.tsx` builds its rows from a `TimelineTrack[]` list
and drags a generic `TimelineItem`, and playback skips removed ranges through
`playbackController.ts` on the existing per-frame clock.

Export keeps ADR 0003's split: the export host renders captions **and, since V2, image overlays**
into the transparent layer; FFmpeg applies cuts, blur and the sound-effect mix to the source before
the layer overlay, driven by a versioned manifest — never by renderer-chosen flags. V1 defines
manifest v2 as a strict superset of X2's v1 (`src/export/plan.ts`), builds it in main from pure
`src/core/composition.ts`, and turns `workers/media/exportArguments.ts` into a deterministic builder
over it. `src/core/layerPlan.ts` maps each sequence frame to its source timestamp and a signature
(reusing `captionFrame`) so the export host repaints only frames that actually differ. **FFmpeg's
filtergraph is still untouched by overlays** — V2 added a second, overlay-carrying frame request
version (`src/export/frameRequest.ts`'s v1/v2 union) the export host paints, and a `--asset <url>`
argv allow-list (`scripts/export-host.mjs`) so the host's own `media:` scheme can load exactly the
asset files the worker resolved, never an arbitrary path. Cuts, sound effects, blur regions
(`split/crop/gblur/overlay`, `enable`d in sequence time, before the zoom crop) and zoom regions
(FFmpeg dynamically scales/crops the composed picture before the transparent host layer, so captions
and host-painted overlays stay pinned) all have dedicated FFmpeg branches — blur regions may overlap
each other in time and in the frame, unlike zoom's one non-overlapping lane.

**Frame-paint effects (schema 9, `project.effects`: vignette, letterbox, fade/dip — [EDITING.md](EDITING.md)
"Frame-paint effects") never reach FFmpeg at all.** They are painted by the export host into the
same transparent layer captions and host-painted overlays already use, with the identical React
components (`CompositionLayers.tsx`, plus a new `overCaption` slot on `CaptionPreview` for fade) live
preview calls — so, unlike blur and zoom, there is no separate FFmpeg branch and no measured
tolerance; parity is exact by construction. The render order within that one shared layer, back to
front: video/image clips, then blur (inside the zoomed picture, all pre-composed by FFmpeg before
this layer even starts) → host-painted image overlays → vignette/letterbox (pinned to the output
frame like an overlay) → captions → fade (the one frame-paint kind that must cover captions too).
`src/core/frameEffects.ts`'s `frameEffectsAt` is the one closed-form evaluator both preview and
`frameRequestAtSequence` (`plan.ts`) call, mirroring `zoomRectAt`'s absolute-time contract; each
effect kind has its own non-overlapping lane (`model.ts`'s schema-9 `superRefine`, one lane per
`kind`), but different kinds may freely overlap, unlike zoom's single lane.

**Authored text (schema 10).** `project.textOverlays` is a separate collection of sequence-timed text items, each with a stable project-wide ID, complete `CaptionStyle` snapshot, item-specific enter/exit motion and a layer order that crosses the fixed caption plane. Schema 9→10 is lossless and initializes `[]`. `textCommands.ts` keeps add/update/move/trim/duplicate/delete/reorder undoable; decorative word-motion boundaries are derived at render time from whole `captionTokens`, never persisted as aligned caption timing. `TextOverlayActor` reuses the caption renderer so shaping, font readiness, styling and template motion match. In the editor, preview double-click creates a title at the mapped composition point or edits an existing title; Titles and the Text lane provide the same playhead-add path. Title templates update appearance while preserving placement and item motion; optional decorative word motion remains distinct from whole-layer transitions. Preview and export evaluate item transitions in absolute sequence time; export manifest v3 carries persisted items and frame request v4 contains only active, ordered text actors. The host waits for each actor's layout/fonts before committing its frame. Text remains absent from transcription, transcript and SRT paths.

**Vector shapes (schema 17).** `project.shapes` holds sequence-timed vector graphics (boxes, circles, lines, arrows, highlighter bars) that share `layerOrder` with authored text: below zero paints under the captions, zero or above over them, ordered by `compareLayered` in preview, the export host and the Layers panel. `ShapeActor` paints one shape as SVG in composition units and `shapeFrameAt` evaluates its draw-on/sweep/fade/pop/slide from sequence time, so preview and export share both. Shapes ride in manifest v3 and in an optional `shapeActors` on frame request v4, and their motion is part of the layer-plan signature. Details: [EDITING.md](EDITING.md) "Shapes (schema 17)".

**Backgrounds (schema 13).** A `color` clip (`src/core/edit.ts`) is a generated video-track item: a solid or two-stop gradient `fill`, an optional preset `motion` (`shift`, `pulse`, `drift`), no asset and a synthetic source range from 0 like an image. Being a clip it inherits track stacking, move/trim/split/ripple, opacity, `rect`, masks, undo and the `clip-add`/`clip-update` MCP verbs; `clip-add` gained `trackIndex` so a background can open a new track at the *bottom* of the stack, since one that lands over the picture would hide it (`backgroundTrackFor`, `src/core/clipEdits.ts`). Schema 12→13 changes no data. `src/core/fill.ts` is the single source of truth for how a background looks at time *t*: the CSS gradient line, the eased loop phase (`0.5−0.5·cos(2πt/period)` counted from the clip's source start, so a moved clip keeps its phase and a split continues its loop) and drift offsets. Preview paints those values with CSS (`CompositionLayers`); export turns the same numbers into FFmpeg filters — the host layer always composites *above* FFmpeg's picture (ADR 0005) so a background must be made by FFmpeg. A solid is the `color` source; a gradient is evaluated once by `geq` along the CSS line and looped (the `gradients` source filter was rejected: its ramp length depends on pixel format and size); shift/pulse `blend` two stills by the shared phase (at ⅛ size on frames ≥480 px, then bilinear-scaled, because per-pixel `blend` ran at ~8 fps on 1080×1920); drift `crop`s an oversized still. A color clip has no manifest input (`inputIndex`/`assetId` absent) and always forces manifest v3 and the stacked route.

**Blend modes (schema 18).** A picture clip's `blendMode` (docs/EDITING.md "Blend modes") is one more reason for the stacked route: each blending clip becomes a full-frame, full-length transparent-padded layer combined with the picture below by `split`/`blend`/`overlay` in `exportFilterGraphV3`, matching preview's `mix-blend-mode` inside an isolated black backdrop. Images that blend are composited by FFmpeg, not host-painted (`imagesHostPainted`, `src/core/hostPainted.ts`).

**Shape blend passes (schema 19).** A shape's `blendMode` cannot be painted by the export host: its layer is transparent and has nothing beneath it to blend with. `graphicsPasses` (`src/core/graphicsPasses.ts`) splits the host-painted graphics into K = 2k+1 bands around k blending shapes (even = normal content, odd = one blending shape; pinned effects band 0, fade the last band); `frameRequestAtSequence(manifest, index, active, pass)` builds one request per band and the worker sends the K sub-frames per output frame down the one caption pipe at K× the rate, planning each band's signature separately so unchanged bands are reused and empty ones never reach the host (`passSignatures`, `PreparedExport.passCount`). `exportFilterGraphV3` `split`s the pipe, `select`s each band back out and composites in order — `overlay` for even bands, the clip `blendChains` for odd ones. The host harness never CSS-blends a shape (`ShapeActor blend={false}`), so preview (CSS `mix-blend-mode`) and export (FFmpeg) each blend exactly once. K = 1 is the untouched single overlay. Glass shapes (schema 21) are odd bands too (`PassBand.kind === 'glass'`; blending and glass shapes share `MAX_PASS_SHAPES` = 8): the band is an opaque map sub-frame (frame request v4 `glassMap: true`, painted by `GlassMapActor`; R/G displacement, B coverage) that `glassChains` in `exportArguments.ts` turns into crop, `gblur`, a saturation `colorchannelmixer`, `displace` and `alphamerge`, overlaid over the shape's span; the glass surface is a normal graphic (`ShapeActor glass={false}`) in the next even band, and a project with glass forces PNG transport (`PreparedExport.pngOnly`). Cap: 8 blending shapes (`MAX_BLENDING_SHAPES`). Parity: `--only shape-blend`; cost and limits: docs/EDITING.md "Blend modes".

**Color: adjustment layers (schema 16, [EDITING.md](EDITING.md) "Color: adjustment layers").** An `adjustment` clip is a generated video-track item like `color` (no asset, synthetic source range) that grades every video/image clip on the tracks below it, for its own time range, instead of painting anything itself. `src/color/` is the pure grade pipeline — camera-log decode, gamut-to-Rec.709, primaries, an optional bundled film look, an intensity mix — evaluated at every point of a 33³ lattice (`bakeGrade`) into one baked `Cube3D`; `composeLuts` folds a stack of adjustment layers into one LUT bottom-up. `src/core/gradeStack.ts`'s `adjustmentsOver`/`gradeStackFor` decide which adjustment clips grade a given picture clip right now, shared verbatim between the export plan (`src/export/plan.ts`, which splits a clip into constant-stack segments before baking, so a change mid-clip becomes sibling manifest clips each with their own `lutId`) and the live preview — the same test in both places is the parity basis, not a coincidence measured after the fact. Preview samples the baked LUT in WebGL2 (`src/captions/GradedVideo.tsx` + `src/color/webglLut.ts`): a graded layer's pooled `<video>` element (normally mounted by `VideoSlot`) is instead mounted under a canvas that redraws it every presented frame (`requestVideoFrameCallback`) through the LUT uploaded as a core-filterable `RGBA16F` `TEXTURE_3D`; a lost context or no WebGL2 falls back to the plain ungraded element with a visible badge. Export writes the same baked LUT as a real `.cube` file per job and inserts FFmpeg's `lut3d=interp=trilinear` into the filtergraph, right after retiming, with an explicit `in_color_matrix`/`in_range` so FFmpeg's YUV→RGB matches Chromium's — the measured macOS synthetic S-Log3 case is recorded in `docs/decisions/evidence/x3-parity-2026-09-24.json` (mean absolute channel delta 5.93/255; see docs/EDITING.md for limits). A user-imported `.cube` is a `lut`-kind project asset, resolved/relinked like media (`electron/projectMedia.ts`) but read directly rather than probed (`electron/main.ts`'s `inspectLut`), and cached as parsed content in the renderer (`src/app/useLutAssets.ts`) rather than a `media://` stream URL.

## Jobs and failures
[T1](TRANSCRIPTION.md) implements `electron/jobScheduler.ts`: queued/running/succeeded/failed/cancelled states with structured progress, kept in strict FIFO order. Every job kind is currently resource-heavy, so by default only one heavy job runs at a time — transcription and export do not compete unless a caller explicitly raises concurrency. `electron/jobs.ts`'s `getJobScheduler()` is the one process-wide scheduler instance transcription (`transcriptionIpc.ts`) and X2's export (`exportIpc.ts`/`exportService.ts`) both enqueue onto, so that arbitration is real rather than each feature queuing only against itself. UI remains responsive. Cancellation terminates child processes and cleans only job-owned temporary files; a job's own `run()` gates its eventual mutation behind an explicit commit step (`ctx.enterCommit()`) so cancellation after valid output exists but before it is applied still prevents the mutation, while a commit already under way is never retroactively relabeled cancelled — X2's export uses this to discard a fully-encoded temporary file rather than renaming it onto the user's destination when cancellation wins the race. Model downloads are explicit, resumable if supported and verified against trusted checksums (T2). Malformed model/backend output is validated before project mutation (T1's `validateTranscriptionOutput`/`validateAlignmentOutput`; the media worker's own result schemas).

## Playback performance
Preview `<video>` elements (`src/playback/videoPool.ts`) always decode *some* real file end to end — sequence resolution (`project.format`) only controls what captions/effects/export composite into, never what preview decodes, so a large source (a 4K import edited for a 1080p delivery) is exactly as heavy to scrub and play in preview as it is to decode natively, regardless of the sequence or export size. Automatic playback proxies are the actual fix: a background, disk-cached, lighter transcode of the *source* file, routed only into preview.

`electron/playbackProxyService.ts` (Electron-free, directly unit-tested like `ExportService`) transcodes through the same media-worker `proxy` operation M4 already defined (WebM/VP8/Opus, capped at 1280 px — `workers/media/proxy.ts`), enqueued on the one shared `getJobScheduler()` so it queues behind, never alongside, a transcription or export the user is actively waiting on (`playback-proxy` job kind, `src/core/jobs.ts`). Before a generated proxy is ever cached or handed to a caller, it is re-probed and its duration checked against the source within a half-second tolerance (`DURATION_TOLERANCE_US`); a proxy that drifts is discarded, never cached, never played — a silently misaligned proxy would otherwise make captions land on the wrong moment. `electron/playbackProxyCache.ts` persists validated results outside Git in the userData cache dir, keyed by fingerprint plus `PROXY_CONVERSION_VERSION`, mirroring `thumbnailCache.ts`/`waveformCache.ts`'s atomic-write-plus-JSON-sidecar pattern; a cache hit is only trusted once the video file is confirmed to still exist. The `media://` protocol handler (`electron/main.ts`) serves proxy files by directory containment (the cache dir only ever holds files this app generated) alongside its existing fingerprint-registry allowlist for source media.

The renderer's `src/core/proxy.ts` defines the pure, unit-tested selection logic — `shouldRequestPlaybackProxy` (mode plus source dimensions decide whether to request one at all: `off` never, `always` unconditionally, `auto`'s default only once the short edge exceeds 1080) and `playbackUrlFor` (which URL preview should actually load, given a proxy's status, the mode and the viewer's own override). `src/app/usePlaybackProxies.ts` is the one hook that ever produces a proxy URL: it requests a proxy at most once per fingerprint per session, tracks per-video status from `media:playback-proxy-status` events, and hands `App.tsx` a wrapped `urlOf` used *only* for the `useProjectPlayback` call that feeds the pooled `<video>` elements. Every other consumer of media URLs — export, transcription, waveform extraction, thumbnails, export parity — keeps calling `useAssetUrls`'s own `urlOf` directly and never sees a proxy; a proxy is preview-only by construction, not by a runtime check any of those paths have to remember to make. "Playback proxies" (Off/Auto/Always, `SettingsDialog.tsx`, renderer-local `localStorage` preference) controls the automatic request; a per-session "Preview: proxy/original quality" toggle over the video preview (`MediaSummary` in `App.tsx`) lets the viewer force full-quality framing regardless of mode.

## Dependency decisions before release
Record pinned runtime, FFmpeg build, speech engine, weights, fonts and installer tooling in a license inventory. Choose the project's source license before publishing. No cloud inference or proprietary rendering service is required. macOS signing and Windows signing are release tasks, distinct from local development.
